# 11 - The web UI

Open `http(s)://<server>:<BRAIN_PORT>` from any machine and log in with `BRAIN_UI_USER` / `BRAIN_UI_PASSWORD`. The
UI is one static page (`brain/ui/`: plain JavaScript and one vendored graph library, no build step), so it works
without internet in any current browser. It follows the operating system's light or dark theme and works on narrow
screens.

## 1. Layout
The menu on the left is grouped:
- **Overview** (start page);
- **Use**: Search, Ask, Enhance prompt, Requirements;
- **Explore**: Learn a project, Code graph, Document graph, Documents;
- **Manage**: Repositories, Settings, Logs.

Under every input box of Search, Ask, Enhance prompt and Requirements, the **prompt analysis** appears while you
type: the language, the key terms as chips (the three most important in bold, each with its kind and score), the
concepts, the search variants and the ignored stop-words.

## 2. Results look the same everywhere
- A row of **source chips**: how many hits came from the code graph, the code vectors, document passages, document
  entities, document facts and code relations; a zero is shown greyed out.
- The pipeline that ran (for example `prompt analysis → code graph search → multilingual code vector index →
  document graph → document → code bridge → code graph expansion → semantic re-rank`), the counts and the time.
- **Code** and **Documents** side by side on wide screens, one below the other on narrow ones.
- Each code hit shows its number, location `repo/path:line-line`, kind and name, which sources found it,
  similarity, signature, callers, callees and parents, and its source (the first three hits open). Buttons:
  *Copy* (the location) and *Graph* (opens the symbol's neighbourhood on the Code graph page).
- Each document passage shows its document and text, with *Markdown* to open what the document was converted to.
  Domain entities and facts follow.
- Ask, Enhance, Learn and Requirements add an **Evidence used** panel: the agent's tool calls in order and the full
  search result the output is based on, and a line with the model, the time and the model calls and tokens used.

## 3. Pages

| Page | What you can do | Status, progress and errors |
|---|---|---|
| **Overview** | see whether everything is ready; recent activity; how to connect an agent (MCP URL and ready-to-paste configuration) | four cards (Code graph, Document graph, Corporate API, Agents) with state, details and models; a card turns red with the engine's error and log tail and offers *Restart engine*; every job with its step and progress bar; refreshes every 4 seconds |
| **Search** | search with *All*, *Code*, *Semantic code* or *Documents*; *Scope* (one repository or a set); *Branch* | per-source counts, pipeline, time, repositories searched, errors per part |
| **Ask** | a question in any language; *Scope*, *Model*, *Branch* | the agent's live steps; the answer with citations; tool calls; notes when the model was unavailable |
| **Enhance prompt** | a short request; *Scope*, *Model*, *Your branch*; optional branch details (repository, merge-base, changed files); *Copy prompt* | live steps; branch warnings inside the prompt |
| **Requirements** | topic, *Scope*, *Format*, *Language*, *Model*; *Write specification*; *Copy Markdown*, *Download .md*, *Add to document graph*; *Edit formats* (load, new from default, save, delete); list of written specifications (open, remove) ([17](17-REQUIREMENTS-WRITER.md)) | progress per capability and section |
| **Learn a project** | *Scope* (one repository or a set), *Model*, optional *Focus*; *Show structure* (languages, packages, entry points, routes and most-connected code of each repository, no model call); *Write project guide* (what it does, how it is built, main flows, where to start reading, key concepts, business rules, with sources); *Copy Markdown*, *Download .md*, *Add to document graph* | the guide job's live steps |
| **Code graph** | per repository or overlay: the architecture view (classes, modules, routes, with method calls, inheritance and imports lifted to their classes); find a symbol; *Show neighbourhood*; an inspector with source and relations, and *Ask about this* (opens Ask with "what does it do, who calls it, which business rules apply" for that symbol) | a message when nothing is indexed yet |
| **Document graph** | the entity graph of all documents, or around one entity (*Focus on this entity*); an inspector with description and relations | a message when the graph is empty or truncated |
| **Documents** | drag and drop or choose many files; *Add a note*; *Markdown* (the converted text); *Remove* | upload job progress; LightRAG pipeline progress; each document's status (pending, processing, processed, failed), chunk count and error |
| **Repositories** | per repository: state, provider, indexed commit, symbols, code vectors, sets, errors, its own webhook (*Copy URL*, *Copy secret*, setup steps), *Update*, *Index a branch…*, overlays (✕ removes); *Update all now*; the repository editor (name, provider, git URL or local path, branch, own token); sets with checkboxes; git-server, update and webhook settings; the branch-drift check; webhook deliveries | sync errors per repository; each delivery with time, source, HTTP status and result |
| **Settings** | every other setting grouped as in [03-CONFIGURATION.md](03-CONFIGURATION.md), with help, default and the restart it needs; raw `LIGHTRAG__` / `CBM__` pass-through values | which engines restart; validation errors; a note when the server itself must be restarted |
| **Logs** | the last lines of the server, document-engine and code-engine logs | |

Secrets are write-only: the UI shows only whether they are set, and an empty field keeps the stored value.

## 4. Security
The session cookie is HttpOnly and SameSite=Strict (and `Secure` with HTTPS). Every request that changes something
sends `X-Brain-UI: 1`. Five wrong passwords from one address lock it for a minute. See [12-SECURITY.md](12-SECURITY.md).
