AI-BRAIN - installation guide

From an empty server to a running code graph, code vectors, document graph, search, ask, enhance and requirements writer, on Windows or Linux, without internet access. Follow the steps in order; every command can be copied as it is.

2. Nothing to download

The folder contains every Python package for Python 3.13 on Windows and Linux (wheels/, about 80 MB), the code engine for both systems (bin/) and the UI's graph library. Setup installs with pip --no-index, so no internet access is needed at any step.

3. Copy the folder to the server

For example to D:\AI-BRAIN. Do not use a folder that OneDrive or another sync tool manages.

For example to /opt/ai-brain, owned by the account that will run the server.

4. Run setup

  1. Open PowerShell in the folder (File Explorer → Shift + right-click → Open PowerShell window here).
  2. powershell -ExecutionPolicy Bypass -File .\setup.ps1
  3. Setup, in this order: finds Python 3.13 and warns if git is missing → creates .venv (recreates it if it was built with another Python) → installs every package from wheels\ → checks the SHA-256 of the code engine against bin\SHA256SUMS and unpacks it → creates .env with a random API token and cookie key and opens it in Notepad (step 5) → creates an empty repos.json → runs brain doctor → offers a firewall rule and a start-at-logon task.
  4. Unattended: .\setup.ps1 -NonInteractive -Firewall -Autostart. A specific interpreter: -Python C:\Python313\python.exe.
  5. Setup can be run again at any time; it keeps .env, repos.json and data\.
  1. cd /opt/ai-brain
chmod +x setup.sh brain.sh
./setup.sh
  2. The same steps as on Windows; .env and repos.json get mode 600, .env opens in $EDITOR (default vi), and setup offers a systemd user service instead of a scheduled task.
  3. Unattended: ./setup.sh --non-interactive --autostart. A specific interpreter: --python /usr/bin/python3.13.

5. Fill in the configuration (.env)

Only these six values are required; everything else has a default and can be changed later in the web UI (Settings, and Repositories for git servers and webhooks).

BRAIN_LLM_BASE_URLhttps://llm-gateway.corp.local/v1the corporate OpenAI-compatible API
BRAIN_LLM_API_KEYsk-…its key
BRAIN_LLM_MODELqwen3-32bdefault chat model for ask, enhance and the requirements writer (documents are indexed without it)
BRAIN_EMBEDDING_MODELbge-m3multilingual embedding model for documents, code vectors and re-ranking

Often useful: BRAIN_PUBLIC_URL (the address shown to users and in webhook URLs), BRAIN_VLM_MODEL (vision model for pictures and scanned pages), BRAIN_CA_BUNDLE (internal CA certificate of the API), BRAIN_GITLAB_URL + BRAIN_GITLAB_TOKEN and BRAIN_TFS_URL + BRAIN_TFS_TOKEN (the corporate git servers and read tokens; repositories can then be written as gitlab:group/project and tfs:Project/repo), BRAIN_GIT_CA_BUNDLE (internal CA of the git servers). Every setting with its meaning: docs/03-CONFIGURATION.md.

Every line must say PASS (WARN lines are hints). Typical fixes:

7. Start

.\brain.cmd serve
./brain.sh serve

The console prints READY: code graph, document graph and the agents (ask, enhance, guide, requirements) are up when everything is ready, usually within a minute; the first index of large repositories continues in the background. Open http://<server>:8765 from any machine and log in. The Overview page shows every component, every job with its progress, and any error with its log.

The server refuses to listen on a network address while BRAIN_UI_PASSWORD is empty.

8. Add repositories and sets

  1. UI → Repositories → Add or edit repositories → Add repository.
  2. Per repository: a name; the provider (empty = detected); either a git URL (gitlab:group/project, tfs:Project/repo or a full URL; the server clones it and follows the branch) or a local path on the server; the branch to follow (default main); an own token only if this repository needs other credentials than its server.
  3. Repository sets: Add set, name it (for example payments) and tick its repositories.
  4. Save repositories and sets: every new repository is indexed at once on its branch (changing a repository's branch re-indexes it). Progress appears on Overview and Repositories; the first index of 10,000 files takes a few minutes, later updates take seconds.

Or edit repos.json directly (see repos.example.json). Search, Ask, Enhance and Requirements can then target one repository or a whole set.

9. Add documents

UI → Documents → drop files (PDF with tables and pictures, Word, PowerPoint, Excel, HTML, CSV, JSON, XML, e-mails, zip archives, EPUB, notebooks, Markdown, text, source code, images) or add a note. Every document is converted to Markdown first (Markdown shows the result), split into passages along its headings and pages, and is searchable as soon as the upload returns; no model call is needed for that. The Vectors and Pictures columns fill up in the background (one batched embedding pass, one vision call per new picture; a text or picture seen before costs no call; local OCR reads pictures when the vision model is missing or slow). Remove deletes a document; Re-index all rebuilds every document from data/originals/.

Requirements: open Requirements → Formats and add your organisation's format (type it, or load a Word or PDF template). No format is built in; the writer refuses to write until one exists.

10. Connect the webhooks

Each repository on the Repositories page shows its own webhook with Copy URL, Copy secret and the setup steps.

GitLab

  1. GitLab → project → Settings → Webhooks → Add new webhook: URL = the copied URL (http://<server>:8765/webhooks/repo/<name>), Secret token = the copied secret, triggers Merge request events and Push events (branch filter: the tracked branch).
  2. Self-managed GitLab: allow requests to the local network from webhooks and integrations (Admin → Settings → Network → Outbound requests).
  3. Press Test → Push events; 202 (accepted) or 200 (ignored) is good.

TFS / Azure DevOps Server

  1. Project settings → Service hooks → Web Hooks: trigger Pull request merge attempted (target branch = the tracked branch), and optionally a second hook Code pushed; URL = the copied URL; basic authentication with any user name and the copied secret as password; resource details: All.
  2. Press Test; 200 or 202 is good.

Local-path repositories need no webhook: they are re-indexed after every pull of their tracked branch. In any other checkout, brain hook makes every git pull of the tracked branch update AI-BRAIN at once.

Every delivery and its result is listed under Repositories → Webhook deliveries. One hook for many repositories is also possible (group-level hooks), and every repository is updated at least every 24 hours anyway (BRAIN_SYNC_INTERVAL_MINUTES, lower it to update more often without webhooks); see docs/09-WEBHOOKS.md.

11. Connect AI agents

.\brain.cmd connect
./brain.sh connect

prints ready-to-paste configuration with your URL and token. In short:

# Claude Code
claude mcp add --transport http --scope user brain http://<server>:8765/mcp --header "Authorization: Bearer <BRAIN_API_TOKEN>"

# opencode: ~/.config/opencode/opencode.json
{"mcp": {"brain": {"type": "remote", "url": "http://<server>:8765/mcp", "enabled": true, "oauth": false,
                "headers": {"Authorization": "Bearer <BRAIN_API_TOKEN>"}}}}

# pi and other agents: REST (put integrations/AGENTS.brain.md into AGENTS.md)
curl -H "Authorization: Bearer <BRAIN_API_TOKEN>" -H "Content-Type: application/json" -d '{"query":"..."}' http://<server>:8765/api/search

Optional: copy integrations/claude-code/brain-enhance.md to ~/.claude/commands/ for a /brain-enhance command, and append integrations/AGENTS.brain.md to CLAUDE.md / AGENTS.md so agents use AI-BRAIN instead of grep, glob and read.

12. Run permanently

Setup's Autostart creates the scheduled task AI-BRAIN (at logon). For a Windows service that runs without anyone logged on, use a service wrapper such as NSSM from your software repository:

nssm install AI-BRAIN "D:\AI-BRAIN\.venv\Scripts\python.exe" "D:\AI-BRAIN\brain.py" serve
nssm set AI-BRAIN AppDirectory D:\AI-BRAIN
nssm start AI-BRAIN

Firewall, if setup did not add it: New-NetFirewallRule -DisplayName "AI-BRAIN" -Direction Inbound -LocalPort 8765 -Protocol TCP -Action Allow

./setup.sh --autostart            # or answer "y" during setup
systemctl --user status ai-brain
journalctl --user -u ai-brain -f
sudo loginctl enable-linger $USER  # start at boot without a login
sudo firewall-cmd --add-port=8765/tcp --permanent && sudo firewall-cmd --reload   # if firewalld is used

13. HTTPS (optional)

Set BRAIN_TLS_CERT and BRAIN_TLS_KEY to PEM files (certificate chain and private key) and restart; then use https:// in webhooks and agent configuration. Alternatively put a TLS reverse proxy in front and set BRAIN_HOST=127.0.0.1.

14. Troubleshooting

SymptomWhat to do
Overview: document graph errorthe data folder is not writable, or SQLite has no full-text search (brain doctor checks both)
Vectors or picture descriptions stay incomplete on the Documents pagethe embedding or vision model failed; fix the URL, key or BRAIN_VLM_MODEL: the next upload or start completes them; keyword search works meanwhile
Repository sync failsthe job error on Overview; check BRAIN_GITLAB_URL / BRAIN_TFS_URL and their tokens (or BRAIN_GIT_TOKEN, or the repository's own token); TLS: BRAIN_GIT_CA_BUNDLE
Webhook answers 401, 404 or 503401: copy the secret again; 404: wrong repository name in the URL; 503: save the repository first
Ask or enhance notes "tool calling not supported"a harmless automatic fallback; or set BRAIN_AGENT_TOOL_CALLING=off
Colleagues cannot open the UIa firewall rule for the port; BRAIN_HOST=0.0.0.0
LogsUI → Logs, or data/logs/server.log, codebase-memory.log

15. Final checklist

  • brain doctor shows only PASS and WARN
  • Overview: all four cards (Code graph, Document graph, Corporate API, Agents) are ready
  • Repositories: every repository indexed, with a commit and code vectors
  • Documents: a test document shows its passages and full vectors; Search finds code and documents with all source chips filled
  • Ask answers a question with sources; Enhance produces a prompt for a bug fix and for a new feature; Requirements writes software requirements in your format from pasted system requirements
  • Each repository's webhook test answers 200 or 202; a merge into the tracked branch shows up in Search
  • An agent lists the brain MCP tools
  • Autostart and firewall configured; data/, .env and repos.json included in backups
